# Expense Tracker — mobile app

This directory has the Dart application code (`lib/`) but not the generated
native Android/iOS project shells — those need to be generated by the
Flutter SDK itself rather than hand-written, since they're version- and
toolchain-specific.

## First-time setup

```
cd apps/mobile-app
flutter create . --platforms=android,ios --project-name expense_tracker_mobile
flutter pub get
```

`flutter create .` on a directory that already has `lib/` and `pubspec.yaml`
only fills in the missing `android/`, `ios/`, etc. folders — it will not
overwrite the existing Dart code.

### Android SMS permissions

After running `flutter create`, add these to
`android/app/src/main/AndroidManifest.xml`, inside the `<manifest>` tag
(alongside the existing `<application>` element, not inside it — except the
`<receiver>` which goes inside `<application>`):

```xml
<uses-permission android:name="android.permission.RECEIVE_SMS"/>
<uses-permission android:name="android.permission.READ_SMS"/>
```

And inside `<application>`:

```xml
<receiver android:name="com.shounakmulay.telephony.sms.IncomingSmsReceiver"
    android:permission="android.permission.BROADCAST_SMS" android:exported="true">
    <intent-filter>
        <action android:name="android.provider.Telephony.SMS_RECEIVED"/>
    </intent-filter>
</receiver>
```

Minimum Android `minSdkVersion` should be at least 21 (check
`android/app/build.gradle`).

### Google Sign-In setup

Sign-in requests Gmail read access in the same consent step, so there is no
separate "connect Gmail" prompt. The app sends Google's `serverAuthCode` to
the backend, which exchanges it for a refresh token.

1. In Google Cloud Console, add an **Android** OAuth client (needs your app's package name + SHA-1 signing fingerprint) and, if you'll test on iOS, an iOS OAuth client — alongside the existing Web client the backend uses.
2. `serverClientId` must be the **Web** client id, not the Android one — that's the client whose secret the backend holds. `npm run dev` passes it automatically from `GOOGLE_CLIENT_ID` in the root `.env` as `--dart-define=GOOGLE_WEB_CLIENT_ID=...`. Running `flutter run` directly means passing it yourself.
3. For Android: no config file is needed for `google_sign_in` itself, but the SHA-1 fingerprint must be registered in Google Cloud Console for sign-in to succeed.
4. For iOS: add the `REVERSED_CLIENT_ID` URL scheme to `ios/Runner/Info.plist` as described in the [google_sign_in iOS setup docs](https://pub.dev/packages/google_sign_in#ios-integration).

### Backend URL

Set `MOBILE_API_URL` in the **root `.env`** (the monorepo has a single env
file). `npm run dev` reads it and passes it to `flutter run` as
`--dart-define=API_URL=...`.

The default, used when running `flutter run` directly, is
`http://10.0.2.2:4000` — the Android emulator's alias for the host
machine's localhost. A physical device can't reach `localhost` on your dev
machine, so set `MOBILE_API_URL` to your machine's LAN IP (e.g.
`http://192.168.1.5:4000`). See `lib/config.dart`.

## Platform note

SMS auto-import only works on Android — iOS does not allow third-party apps
to read SMS. On iOS the app still works for Gmail-based auto-import and
manual entry; the SMS settings toggle is hidden on iOS.

## Running

```
flutter run
```
